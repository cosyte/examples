# cosyte/examples

Runnable starters for the `@cosyte/*` healthcare libraries. Each top-level folder with a tracked
`package.json` is one starter: its own committed `package-lock.json`, `src/`, `test/` and README,
`npm start` to run it and `npm test` to run it again and assert its key output, offline, on Node 22
or later. The repo ships no package: no root `package.json`, no changeset, no `CHANGELOG.md`.

## Gate

Run these from the repo root, in this order. There is nothing to install at the root.

1. `bash scripts/check-no-emdash.sh`
2. In every starter, `npm ci`, then `npm test`. CI lists the starters this way:
   `git ls-files -- '*/package.json' | awk -F/ 'NF == 2 { print $1 }'`
3. Step 2 again on Node 22, the floor, for each starter the change touches:
   `mise exec node@22 -- npm ci`, then `mise exec node@22 -- npm test`.

Step 1 is `no-emdash.yml`'s `no-emdash` check. On a pull request it also scans the title, the body
and the commit messages (the script's `--stdin` mode), since a squash merge makes them the commit on
`main`, and editing the title or body runs it again. Steps 2 and 3 are `starters.yml`: every starter
on Node 22 and 24, and `All starters` is the one check that stands for the whole matrix, so a new
starter folder is tested with no workflow edit. `starters.yml` also runs nightly on `main`, from the
lockfiles.

## Hazard: a starter gets copied into production

This repo is public, and a starter exists to be cloned and built on: what it does, an integration
will do with real patients. So every message, document and image is synthetic (generated by
`@cosyte/synth` or written by hand) and must not pass for a real record, and every pattern must be
safe to copy. The listener binds `127.0.0.1` only; identifiers never reach a log, an error, a
manifest or a summary meant to be value-free; a check exits nonzero when it fails rather than
printing a result. A change that makes data look more real or a pattern less safe is the risk here,
even when every test is green.

## Rules that bind here

Each names the pull request whose failure proved it.

- Move a starter to a new library version by regenerating its `package-lock.json` from scratch
  (`rm -rf node_modules package-lock.json && npm install`), then check that every `@cosyte` package
  in it resolved to the new line (`npm ls --all`). cli-tour's old lockfile held `@cosyte/fhir`
  0.0.10, which every peer range still accepted, so an in-place install kept it (#8).
- A README says only what its starter runs and its test asserts. #7 dropped a claim that
  `validateResource` checks a Bundle's `urn:uuid` references (it counts them as external), and #10
  narrowed three sentences that said more than the starters show.
