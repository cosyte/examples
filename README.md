# Cosyte examples

> Runnable end-to-end starters for the `@cosyte/*` healthcare libraries, on synthetic data only.

[![CI](https://img.shields.io/github/actions/workflow/status/cosyte/examples/starters.yml?branch=main&label=CI)](https://github.com/cosyte/examples/actions/workflows/starters.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://github.com/cosyte/examples/blob/main/LICENSE)

Runnable end-to-end starters for the `@cosyte/*` healthcare libraries. Each starter is a small,
complete program you can clone, install, and run in a minute. Every message, document, and image
here is synthetic: generated by `@cosyte/synth` or written by hand for the example. None of it is
real patient data.

## Why this exists

A library's reference tells you what each function does; a starter shows several of them working
together in a complete program you can run. Each starter here is small enough to read in one
sitting, runs with no build step, no database, and no network beyond localhost, and asserts its
own key output in its tests, so you can clone one and build on it.

---

## Status

Ten starters, listed below. Each sets its `@cosyte/*` versions in its own `package.json` and commits
its `package-lock.json`, and CI runs every one of them on Node 22 and 24. This repository ships no
package: there is no root `package.json`, no changeset, and no `CHANGELOG.md`. A version tag releases
the starters' pages for [docs.cosyte.com](https://docs.cosyte.com/examples/?utm_source=github&utm_medium=readme&utm_campaign=evergreen&utm_content=examples).

## Run a starter

```bash
git clone https://github.com/cosyte/examples.git
cd examples/deid-hl7
npm install
npm start
npm test
```

Each starter needs Node 22 or later and nothing else: no build step, no database, no network beyond
localhost. `npm start` runs it and prints what it did. `npm test` runs it again and asserts the key
output. Each starter's README shows the expected output and walks through the code.

---

## Layout

Each top-level folder with a tracked `package.json` is one starter and its own npm project: a
committed `package-lock.json`, `src/`, `test/`, and a README. There is nothing to install at the
root. A starter's integration tests live in `test/integration/`, tagged by file name:
`*.fast.test.js` run in `npm test`, `*.full.test.js` only in `npm run test:full`. They call the
libraries' public APIs only.

`docs-content/` holds the docs site's pages: an overview that routes by what you want to build, one
page per starter, and the guides around them. Each starter page's expected output and code are
generated from the starter by `scripts/docs-content.mjs`, and CI fails when a starter has no page or
a page no longer matches its starter.

---

## Versions and CI

Each starter sets its `@cosyte/*` versions in its own `package.json` and commits its
`package-lock.json`. CI installs every starter from its lockfile and runs `npm test` on Node 22 and
24, on every pull request and every push to `main`; `npm test` includes each starter's fast
integration tests, which chain the libraries through their public APIs. The full integration suite,
`npm run test:full` in every starter with its seed sweeps, runs nightly on `main`, and a library's
release can run it against the package it is about to publish. Changes reach `main` only through pull requests
that pass `All starters` (every starter on both Node lines) and `no-emdash`.

## Security

Report a vulnerability privately, as the [security policy](https://github.com/cosyte/.github/blob/main/SECURITY.md) describes, never in a public issue.

### PHI and safety

Synthetic data only. Every message, document, and image here is generated by `@cosyte/synth` or
written by hand, and must not pass for a real record. Real patient data never enters this
repository, a fixture, or a log.

A starter exists to be cloned and built on, so every pattern in it is meant to be safe to copy. The
MLLP listener in `hl7-mllp-listener` binds `127.0.0.1` only, and no starter reaches the network
beyond localhost. What you build from a starter, and the data you run through it, are yours to
secure: transport, storage, access control, and what reaches your logs.
