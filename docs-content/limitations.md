# Limitations

What the starters, taken together, do not do. Each starter's page lists its own under "Before you
build on it".

## Data

- **Synthetic only.** Every message, document and image is generated by `@cosyte/synth` or written by
  hand. A pattern that is safe to copy is not a reviewed integration: what you build from it, and the
  data you run through it, are yours to secure.
- **Nothing identifying is printed.** A starter prints no name, record or member number, date of
  birth, address, phone number, free-text note or whole message, synthetic as they are: see
  [What is safe to log](./how-the-starters-are-built.md#what-is-safe-to-log). To see a value, read
  it in code; the output alone will not show it.

## De-identification

- **Not certified.** The output of `deid-hl7`, `dicom-metadata` and `cosyte redact` in `cli-tour` is
  transformed per the configured Safe Harbor policy. It is not certified as de-identified, and
  `@cosyte/deid` renders no Expert Determination.
- **Metadata only for DICOM.** `dicom-metadata` never inspects pixels.
- **Passed-through positions.** A position no rule names passes through unchanged, such as the message
  control ID (`MSH-10`) and the patient location (`PV1-3`) in `deid-hl7` and `cli-tour`.

## Transport

- **Loopback, cleartext.** The MLLP listener binds `127.0.0.1` and speaks plain MLLP, with no TLS and
  no de-duplication of a resent message.

## Validation

- **No conformance verdict.** Zero errors from `@cosyte/fhir` in `hl7-to-fhir` is not a full FHIR
  conformance verdict, and `cosyte validate` calls an HL7 v2 message valid when it parses.

## Versions

- **0.x libraries.** Every `@cosyte/*` library a starter depends on is below 1.0. Below 1.0 a
  breaking change can ship in a patch release, so a starter's caret range (`^0.1.0`) does not protect
  it; the committed `package-lock.json` does. See [Update the libraries in a starter](./update-the-libraries.md).
