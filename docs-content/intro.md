# Examples

[cosyte/examples](https://github.com/cosyte/examples) holds ten runnable starters for our `@cosyte/*`
healthcare libraries. A library's reference tells you what each function does; a starter shows
several of them working together in a complete program you can run. Each one is small enough to read
in one sitting, runs with no build step, no database and no network beyond localhost, and asserts its
own key output in its tests, so you can clone one and build on it.

Every message, document and image in them is synthetic: generated by `@cosyte/synth` or written by
hand for the example. None of it is real patient data.

## Pick a starter by what you want to build

| You want to | Start from | Libraries |
| --- | --- | --- |
| Receive HL7 v2 messages from another system over MLLP, and acknowledge each one | [hl7-mllp-listener](./starter-hl7-mllp-listener.md) | mllp, hl7, synth |
| Turn HL7 v2 admits into FHIR R4 resources | [hl7-to-fhir](./starter-hl7-to-fhir.md) | transform, fhir, hl7, synth |
| Share HL7 v2 messages with identifiers removed | [deid-hl7](./starter-deid-hl7.md) | deid, hl7, synth |
| Do any of that from the command line, with no code | [cli-tour](./starter-cli-tour.md) | cli, hl7, synth |
| Check a patient's insurance coverage before a visit | [x12-eligibility](./starter-x12-eligibility.md) | x12, synth |
| Post payments from an insurer's remittance | [x12-remittance](./starter-x12-remittance.md) | x12, synth |
| Bill a pharmacy claim and read the payer's answer | [ncpdp-claim](./starter-ncpdp-claim.md) | ncpdp, synth |
| Read results from a lab analyzer | [astm-lab-results](./starter-astm-lab-results.md) | astm, synth |
| Read a clinical document, such as a continuity of care document | [ccda-summary](./starter-ccda-summary.md) | ccda, synth |
| Read imaging metadata, and share a header with identifiers removed | [dicom-metadata](./starter-dicom-metadata.md) | dicom, deid |

Each starter's page says what it shows, how to run it and what its test checks, then gives what it
prints and every file of its code.

## What they are, and what they are not

- **Complete programs.** Each starter is its own npm project with a committed lockfile, `src/`,
  `test/` and a README. `npm start` runs it, and `npm test` runs it again and asserts its output.
- **Safe to copy.** A starter exists to be cloned and built on, so every pattern in it is meant to be
  safe to copy: the MLLP listener binds `127.0.0.1` only, the de-identification manifests carry no
  value, and a check exits nonzero when it fails rather than printing a result. See
  [How the starters are built](./how-the-starters-are-built.md).
- **Not a product.** What you build from a starter, and the data you run through it, are yours to
  secure: transport, storage, access control and what reaches your logs.
