# AGENTS.md

Runnable starters for Cosyte's `@cosyte/*` healthcare libraries. Each top-level folder with a
tracked `package.json` is one starter and its own npm project: a committed `package-lock.json`,
`src/`, `test/`, and a README. The repository ships no package: no root `package.json`, no
changeset, and no `CHANGELOG.md`.

`docs-content/` holds the pages docs.cosyte.com renders, after the docs-content standard in
cosyte/config: the overview (`intro.md`), the fixed pages, the guides, and one page per starter,
`starter-<name>.md`. A starter page is written by hand down to its `## Expected output` heading;
from there to the end, its expected output (from the starter's README) and its files are generated
by `node scripts/docs-content.mjs`. A new starter is a new page, listed in `sidebars.json` and linked
from `intro.md`; a changed starter is a regenerated page, committed with it. A tag `vX.Y.Z` on `main`
releases the pages (`.github/workflows/release.yml`). `scripts/` holds those scripts and their tests,
with no `package.json`, so it is never read as a starter.

## Build and test

Use Node.js 22 or later and npm. There is no build step, and nothing to install at the root.

```sh
cd deid-hl7    # any starter
npm ci
npm start      # runs the starter
npm test       # runs it again and asserts its key output, offline, with the fast integration tests
npm run test:full  # every test, the integration seed sweeps included, helpers held to 100% coverage
```

A starter's integration tests live in `test/integration/`, tagged by file name: `*.fast.test.js` run
in `npm test`, `*.full.test.js` only in `npm run test:full`. They call the libraries' public APIs only.
A defect a test finds in a library is reported upstream and marked with a `todo` that names it, never
worked around in the test.

## The gate

Run these from the repository root, in this order, before you push:

1. The shared gates, at the version the workflows pin:
   `npx -y @cosyte/script-utils@0.1.4 no-emdash`, then the same with `claude-card` in place of
   `no-emdash`.
2. In every starter, `npm ci`, then `npm test`, and `npm run test:full` in each starter the change
   touches. CI lists the starters this way:
   `git ls-files -- '*/package.json' | awk -F/ 'NF == 2 { print $1 }'`
3. Step 2 again on Node 22, the floor, for each starter the change touches:
   `mise exec node@22 -- npm ci`, then `mise exec node@22 -- npm test`.
4. `actionlint`, when the change touches `.github/workflows/`.
5. When the change touches a starter, `docs-content/` or `scripts/`: `node scripts/docs-content.mjs`
   (it rewrites the generated parts of the starter pages; commit what it wrote), then
   `node scripts/docs-content.mjs --check` and `node --test scripts/*.test.mjs`.

CI runs every starter on Node 22 and 24.

## Data

Synthetic data only. Every message, document, and image here is generated by `@cosyte/synth` or
written by hand, and must not pass for a real record. Real patient data never enters this
repository, a fixture, or a log.
